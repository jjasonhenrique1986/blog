The goal of this post is to show how to create a synthetic canary on
AWS. It's a CloudWatch feature whose main job is to test
whether a URL or an API is
returning a success status (HTTP 200), with a check every minute,
for example. This feature exists in other observability
tools I've worked with, such as Dynatrace and Datadog.

For more information, see the [CloudWatch
Synthetics documentation](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/CloudWatch_Synthetics_Canaries.html).

## Prerequisites

To test this AWS service, I created a Python API using
FastAPI. To learn more about what FastAPI is and how to
create an API with FastAPI, see the [official FastAPI
documentation](https://fastapi.tiangolo.com/) (in Portuguese, there's also
[this Python Academy
tutorial](https://pythonacademy.com.br/blog/como-usar-o-fastapi-para-construir-apis-no-python)).

To install FastAPI I'll use an EC2 instance with the following
configuration:

![Summary of the EC2 instance creation with Ubuntu 22.04 and type t2.micro](/images/synthetic-2.webp)

**Keep in mind that this EC2 instance must have a public IP.**

## Installing FastAPI

After creating the EC2 instance on AWS, run the following commands
to install FastAPI:

``` bash
sudo apt update
sudo apt install python3-pip -y
pip install fastapi
pip install uvicorn
```

To validate the installation, run the command below:

``` bash
pip show fastapi
```

It should return something like the image below:

![pip show fastapi output showing version 0.89.1 installed on the instance](/images/synthetic-3.png)

After installing FastAPI, create the **main.py** file
as below:

``` python
from fastapi import FastAPI

app = FastAPI()

@app.get("/")

def index():
    return "Hello World"
```

After saving the file above, run the command below to
start FastAPI:

``` bash
uvicorn main:app --host 0.0.0.0 --port 8080
```

In my case I'm using port 8080. You'll need to open this
port in the EC2 instance's security group, as in the image below:

![Security group rule allowing port 8080 from 0.0.0.0/0](/images/synthetic-4.webp)

Using your EC2 instance's public DNS or public IP on port 8080, we should
get a result similar to the image below:

![Browser accessing the API on port 8080 of the EC2 instance and showing Hello World](/images/synthetic-5.webp)

## Configuring Synthetics Canaries

To continue configuring CloudWatch Synthetics Canaries,
you need to have already created the API as in the section above.

To start the configuration, go to **Application
Monitoring** \>\> **Synthetics Canaries** in the **CloudWatch** service,
as in the image below:

![CloudWatch Application monitoring menu with the Synthetics Canaries option](/images/synthetic-6.webp)

You'll see a screen like the one below:

![CloudWatch Synthetics Canaries screen with no canary created yet](/images/synthetic-7.webp)

To create one, just click **Create Canary** and you'll see
the screen below:

![Create canary screen with the Use a blueprint option and the Heartbeat monitoring blueprint selected](/images/synthetic-8.webp)

In this first section we can use blueprints already created by AWS,
use our own scripts or import from an S3 bucket. In my case I'll
use the first option.

![Canary builder section with the name helloworld and the API URL on port 8080](/images/synthetic-9.webp)

In this second section you set the canary's name and the endpoint URL
that will be checked.

![Canary script editor with the syn-python-selenium-1.3 runtime and the Python script generated by the blueprint](/images/synthetic-10.png)

In this third section you choose the runtime that will run. In my
case I chose the runtime that uses python3.8 + selenium + chromium,
but there are other options. You can also configure environment
variables for running the script.

![Canary schedule configured to run continuously every 1 minute](/images/synthetic-11.webp)

In this fourth section you configure how often the endpoint URL
check runs.

Other options you can configure on the same screen:

-   Retention time for the results;
-   Bucket where the results are saved;
-   Creating an IAM Role;
-   Creating a CloudWatch alarm;
-   Running the check only inside a specific VPC;
-   Tags;

After it's created, you'll see the dashboard below:

![Success message after creating the helloworld canary, still in the Creating state](/images/synthetic-12.webp)

![helloworld canary running with Passed status and 100% success](/images/synthetic-13.webp)

I stopped the API to check whether the canary reports the failure,
as in the image below:

![helloworld canary with Failed status after the API stopped responding](/images/synthetic-14.webp)

You can also create Synthetics Canaries with Terraform, using the
[aws_synthetics_canary](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/synthetics_canary)
resource.

## Conclusion

The purpose of this post was to show how to create a simple API and
check it with CloudWatch Synthetics Canaries.
